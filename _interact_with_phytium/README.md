# 飞腾派交通标志识别系统

一个基于飞腾派的完整交通标志检测与识别系统，采用主机-飞腾派主核-飞腾派从核的三层架构，实现实时视频流的交通标志检测、分类和结果可视化。

## 系统架构概览

```
┌─────────────┐     UDP分片传输     ┌─────────────────┐     OpenAMP     ┌─────────────────┐
│   主机(PC)   │ ◄──────────────► │  飞腾派主核     │ ◄──────────► │  飞腾派从核     │
│             │                    │                 │                │                 │
│ • 视频采集   │                    │ • 分片重组      │                │ • 结果确认      │
│ • 分片发送   │                    │ • AI推理        │                │ • 协议解析      │
│ • 结果可视化 │                    │ • 结果转发      │                │ • 数据验证      │
└─────────────┘                    └─────────────────┘                └─────────────────┘
```

## 完整工作流程

### 1. 视频帧采集与发送 (主机端)
- **视频源处理**: 读取视频文件或摄像头数据
- **关键帧提取**: 按配置间隔(默认每5帧)提取关键帧进行推理
- **图像编码**: 将关键帧编码为JPEG格式以减少传输数据量
- **分片传输**: 当JPEG数据超过UDP包大小限制时，自动分片传输
- **帧缓存管理**: 缓存已发送的帧，等待对应的检测结果返回

### 2. 数据接收与重组 (飞腾派主核)
- **UDP监听**: 监听主机发送的视频帧数据包
- **分片重组**: 
  - 解析分片协议头 (魔数验证、帧ID、分片信息)
  - 按帧ID分组管理分片数据
  - 重组完整帧数据并验证完整性
  - 自动清理超时的不完整帧数据

### 3. AI推理处理 (飞腾派主核)

#### 3.1 两阶段推理架构
系统采用检测+分类的两阶段推理架构，实现高精度的交通标志识别：

**第一阶段：目标检测**
- **模型**: YOLOv5检测模型 (输入640×640，输出25200个候选框)
- **功能**: 定位图像中的交通标志位置，提供边界框坐标
- **输出**: 每个检测框包含 [x_center, y_center, width, height, objectness, class_prob]

**第二阶段：目标分类**  
- **模型**: 专用分类模型 (输入224×224，输出31个交通标志类别)
- **功能**: 对检测到的交通标志区域进行精确分类
- **优势**: 专门针对交通标志优化，分类精度更高

#### 3.2 详细推理流程

**阶段一：目标检测与轻量级NMS**
```python
# 1. 图像预处理
图像输入 → letterbox缩放(640×640) → 归一化[0,1] → CHW格式转换

# 2. YOLOv5检测推理
输入: (1, 3, 640, 640)
输出: (1, 25200, 6) # [cx, cy, w, h, objectness, class_prob]

# 3. 第一阶段轻量级NMS
- 过滤置信度 < 0.15 的检测框
- 坐标格式转换: (cx,cy,w,h) → (x1,y1,x2,y2)  
- 轻量级NMS: IoU阈值=0.95，去除高度重叠的冗余框
- 按置信度排序，保留前100个高质量候选框
- 坐标空间转换: letterbox → 原始图像空间
```

**阶段二：批量分类推理**
```python
# 4. 候选框预处理
for 每个检测框:
    裁剪区域 → resize(224×224) → BGR→RGB → 归一化 → CHW格式

# 5. 批量分类推理  
批量输入: (N, 3, 224, 224)
批量输出: (N, 31) # 31个交通标志类别的概率分布
softmax激活 → 获取最高概率类别和置信度

# 6. 结果整合
综合置信度 = 检测置信度 × 分类置信度
构建完整结果: {bbox, detect_conf, class_conf, class_id, class_name}
```

**阶段三：分类NMS后处理**
```python
# 7. 按类别分组NMS
按class_id分组 → 过滤综合置信度<0.3 → 类内NMS(IoU=0.5) → 最终结果
```

#### 3.3 推理性能优化特点
- **两阶段NMS设计**: 第一阶段快速过滤低质量框，第二阶段精确去重
- **批量分类推理**: 一次性处理多个目标，显著提升多目标场景性能
- **内存管理**: 通过候选框数量限制控制内存使用
- **坐标精确转换**: 保证检测框在不同空间的准确映射

### 4. 结果转发与确认 (主核→从核→主核)
- **OpenAMP通信**: 主核通过OpenAMP将JSON格式的推理结果发送给从核
- **协议解析**: 从核解析推理结果的协议数据结构
- **数据验证**: 从核验证推理结果的完整性和格式正确性
- **结果确认**: 从核确认后将结果返回给主核
- **UDP回传**: 主核将确认后的结果通过UDP发送回主机

### 5. 结果可视化 (主机端)
- **结果接收**: 接收飞腾派返回的检测结果JSON数据
- **帧匹配**: 根据frame_id匹配对应的原始视频帧
- **可视化绘制**: 在原始帧上绘制检测框、类别标签和置信度
- **实时显示**: 实时显示带有检测结果的视频画面
- **视频保存**: 可选择保存带检测结果的视频文件

## 核心技术实现

### 分片传输协议
```c
// 分片协议头结构 (16字节)
struct FragmentHeader {
    uint8_t  magic[4];      // 魔数 "FSTM"
    uint32_t frame_id;      // 帧ID (大端序)
    uint32_t total_size;    // 总数据大小 (大端序)
    uint32_t fragment_info; // 分片信息 (大端序)
                           // 高16位: 总分片数
                           // 低16位: 当前分片索引
};
```

### OpenAMP通信协议
```c
// 主核-从核通信协议
typedef struct {
    uint32_t command;           // 命令字
    uint16_t length;            // 数据长度
    char data[MAX_DATA_LENGTH]; // JSON数据内容
} ProtocolData;

// 命令定义
#define DEVICE_CORE_START       0x0001  // 开始任务
#define DEVICE_CORE_SHUTDOWN    0x0002  // 关闭核心  
#define DEVICE_CORE_CHECK       0x0003  // 检查消息
#define DEVICE_INFERENCE_RESULT 0x0004  // 推理结果
```

## 故障排除

### 常见问题
1. **网络连接失败**: 检查IP地址配置和网络连通性
2. **模型加载失败**: 确认模型文件路径和格式正确性
3. **分片重组超时**: 调整FRAGMENT_TIMEOUT参数
4. **检测结果不匹配**: 检查frame_id的一致性
